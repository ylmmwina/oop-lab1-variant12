# Лабораторна робота № 1

**Дисципліна:** об’єктно-орієнтоване програмування  
**Варіант:** 12 — «Мобільний зв’язок»  
**Мова програмування:** Java

## Мета роботи

Застосувати принципи об’єктно-орієнтованого програмування для моделювання тарифів мобільної компанії. Реалізувати обробку колекції об’єктів, модульне тестування та використання системи контролю версій Git.

## Умова завдання

Визначити ієрархію тарифів мобільної компанії. Створити список тарифів компанії. Порахувати загальну кількість клієнтів. Провести сортування тарифів на основі розміру абонентської плати. Знайти тариф у компанії, що відповідає заданому діапазону параметрів.

## Реалізовані можливості

- Створення голосових, інтернетних та комбінованих тарифів.
- Формування списку тарифів мобільної компанії.
- Підрахунок загальної кількості клієнтів.
- Сортування тарифів за зростанням місячної абонентської плати.
- Пошук тарифів за діапазонами абонентської плати, кількості хвилин та обсягу інтернету.
- Перевірка коректності початкових даних.
- Автоматична демонстрація результатів у консолі без інтерактивного меню.

## Структура програми

Основний код розміщено в `src/main/java/ua/edu/lab1`, тести — у `src/test/java/ua/edu/lab1`.

| Пакет | Клас | Призначення |
| --- | --- | --- |
| `model` | `Tariff` | Абстрактний базовий клас зі спільними характеристиками тарифів |
| `model` | `VoiceTariff` | Голосовий тариф із пакетом хвилин |
| `model` | `DataTariff` | Тариф із пакетом інтернету |
| `model` | `CombinedTariff` | Тариф із пакетами хвилин та інтернету |
| `service` | `MobileCompany` | Зберігання списку тарифів, підрахунок клієнтів, сортування та пошук |
| `service` | `TariffCriteria` | Діапазони параметрів та перевірка відповідності тарифу |
| `app` | `Main` | Точка входу, демонстраційні дані та консольне виведення |

## Застосування принципів ООП

**Абстракція.** Клас `Tariff` визначає спільні властивості тарифів та абстрактний метод `getType()`.

**Інкапсуляція.** Поля тарифів є приватними та незмінними. Дані перевіряються в конструкторах. Компанія створює захисні копії колекцій, щоб зовнішній код не міг змінити її внутрішній список.

**Успадкування.** Класи `VoiceTariff`, `DataTariff` і `CombinedTariff` успадковують `Tariff`.

**Поліморфізм.** Об’єкти різних типів зберігаються в `List<Tariff>`. Виклик перевизначеного методу `getType()` залежить від фактичного типу об’єкта.

Компанія містить колекцію тарифів через композицію: успадкування між компанією та тарифом не використовується.

## Запуск

### IntelliJ IDEA

1. Відкрити `pom.xml` як Maven-проєкт.
2. Встановити JDK 25 як Project SDK та JDK для запуску Maven.
3. Дочекатися завантаження залежностей.
4. Запустити метод `main()` класу `ua.edu.lab1.app.Main`.

### Командний рядок

За наявності Maven та JDK 25 у середовищі виконати в корені проєкту:

```shell
mvn clean verify
java -jar target/mobile-company-1.0.0.jar
```

## Тестування

Для запуску тестів і формування звіту покриття:

```shell
mvn clean verify
```

В IntelliJ IDEA цю операцію можна виконати через панель **Maven → Lifecycle → verify**, використовуючи вбудований Maven.

Тести перевіряють конструктори та властивості тарифів, некоректні дані, підрахунок клієнтів, сортування, включні межі пошуку, порожні результати, захист колекцій і консольний вивід. Mockito використовується для ізольованої перевірки підрахунку клієнтів.

Під час перевірки на OpenJDK 25.0.3 та Maven 3.9.11 успішно виконано **19 тестових запусків**. Покриття основного коду за JaCoCo становило **100% рядків та гілок**. У `pom.xml` встановлено відповідні мінімальні пороги для фази `verify`.

Після успішного виконання `verify` локальний HTML-звіт доступний у файлі:

```text
target/site/jacoco/index.html
```

Це локальний файл, який потрібно відкрити у браузері. Він створюється під час збирання та не зберігається в Git.

## Демонстраційні дані та результати

Наведені дані є навчальними й не описують пропозиції реального оператора.

| Тариф | Тип | Плата, грн/місяць | Клієнти | Хвилини | Інтернет, ГБ |
| --- | --- | ---: | ---: | ---: | ---: |
| Максимум | Комбінований | 450.00 | 800 | 1000 | 50 |
| Розмова | Голосовий | 120.00 | 1200 | 300 | 0 |
| Онлайн | Інтернет | 200.00 | 600 | 0 | 40 |
| Баланс | Комбінований | 250.00 | 1500 | 500 | 20 |

Загальна кількість клієнтів: 800 + 1200 = 2000; 2000 + 600 = 2600; 2600 + 1500 = **4100**.

Порядок після сортування: **Розмова → Онлайн → Баланс → Максимум**.

Для діапазонів **200–300 грн/місяць**, **0–600 хвилин** і **20–40 ГБ** результат пошуку: **Онлайн, Баланс**. Межі включні; усі три умови застосовуються одночасно.

## Особливості моделі

- Припускається, що кожен клієнт належить одному тарифу.
- Кількості клієнтів підсумовуються з використанням типу `long`.
- Абонентська плата зберігається як `BigDecimal` із двома десятковими знаками. Округлення не виконується: значення з ненульовими дробовими частинами копійки відхиляються.
- Назва тарифу має бути непорожньою, числові параметри — невід’ємними.
- За однакової абонентської плати сортування зберігає початковий взаємний порядок тарифів.
- Пошук повертає всі відповідні тарифи; за відсутності збігів — порожній список.
